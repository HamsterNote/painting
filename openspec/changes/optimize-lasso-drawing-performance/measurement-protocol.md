## 接受或废弃一轮的条件

`lasso-host-gate.mjs`按进程CPU affinity读取 `/proc/stat`，500ms窗口计算真正idle比例（iowait/steal另列，不把guest重复加进总量），并记录窗口前后三项load。当前可用6核，取前后一分钟load较大值，超过3立即拒绝；额外要求idle≥50%。不可读、缺失、回退的CPU时钟直接报错，禁止默认通过。

`lasso-clean-pair.mjs`在构建/启动浏览器前做门禁，最多3次，相隔30秒。已污染时不启动性能矩阵。启动后每对、每个样本前后都检查；任何一方污染则整对废弃，冷/热一组不完整也不接受。所有尝试留档，不只留最好轮次。每格最多3次，失败停止整矩阵；退出码2表示没有完整有效数据，不表示产品性能失败。

版本A固定为main 3ac6e585，B固定为PR53 c23d4ca；所有painting源码和fixture均从对应git对象装载。依赖锁文件和painting包清单两版无差异。CPU、操作、分配三种模式各跑local/dense × 500/1000笔 × 3轮。每轮创建两个新context，冷态按AB、热态按BA，下一轮反向。相邻样本间隔不得超过30秒；同一对最终有序命中ID必须相同。原版81bff35只用于此次人类手感对照，不混入这个内核A/B比较。

正式采集保持headed Chromium/Xvfb、6×CPU降频。Xvfb并非实体显示器；输入内核是固定600点轨迹，本工具不驱动React/UI。**cold仅指已准备几何上的首次内核查询，没有合成预热；不是应用首次真实套索。** prepareLayeredObjectQuery、fixture构造在边界外。准备成本和渲染/合成仍须在UI验收trace中另测，不能用这个更窄的边界宣称端到端达标。

## 指标及边界

- **查询线程CPU ms**：`kernel:start`/`kernel:end`包围createLayeredLassoQuery和完整step，包括套索规范化、查询索引/候选及逐对象精算。使用同一renderer线程的 `(end.tts-start.tts)/1000`；时钟缺失、线程不同或边界不唯一直接拒绝，不以Paint、performance.now或RunTask墙钟替代。线程CPU排除OS等待，但仍可能受频率、缓存、JIT等因素影响，因此仍执行负载门禁与交替配对。
- **操作计数**：候选数、processed精算数、有序命中ID；探针bundle单独记录快速谓词段对检查、旧距离谓词段对检查及reference兜底次数。reference次数不是polyclip内部边对数，也不是严格布尔运算调用数。计数只注入独立bundle，不修改产品热路径；带计数的CPU读数不进主计时。
- **GC**：查询边界内同renderer线程的MinorGC/MajorGC事件次数。它不是所有后台GC线程工作量总和。
- **分配**：另开context/轮次，用HeapProfiler 32KiB采样且包含已被Minor/MajorGC回收的对象，报告 `sampledEstimatedAllocatedBytes`。这是采样估计，可能包含CDP调用、结果序列化和追踪控制开销，不是精确“每次查询分配字节”；原始profile一并保存。分配探针的CPU不用于主指标。
- **Paint和长任务**：旧 `lasso-final-ui.mjs`也增加开跑及手势前后门禁；只作端到端验收辅助。禁止把不同调用、不同时间的UI结果拼成A/B加速比。冷态和热态分别保留，UI门槛保持未验收。

## 复现与验证

在仓库根目录执行：

```sh
node --test scripts/perf/lasso-host-gate.test.mjs
node scripts/perf/lasso-measurement-smoke.mjs
node scripts/perf/lasso-clean-pair.mjs artifacts/research/lasso-measurement/new-attempt
```

最后一个命令必须用新输出目录，已有run.json则拒绝覆盖。smoke是headless功能测试，允许在忙碌主机执行，结果不作为性能证据；它验证线程时钟、独立探针、两版命中一致，以及三版相同文档和PR53拖动零查询/松手一次查询。核验参数 `diagnostics=1`开放三版共有的控制器访问（原版没有lassoPerf开关），会显示诊断UI，因此只用于功能检查；公开试用入口不带该参数。

单测覆盖6核load=3/3.01边界、空闲CPU、坏计数器、整对废弃、过时间隔、有序命中不一致、AB/BA顺序、CPU时钟缺失或跨线程；放大墙钟而保持线程时钟时，CPU结果必须不变。

实际运行结果见本轮附件；没有通过门禁的成对样本时不填写性能对比表、不计算加速倍数。OpenSpec 6.4、7.3、8.2及实体设备验收继续保持未完成。
