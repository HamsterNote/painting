# Spec Delta

## Purpose

规定 **以 Web 为正式验收面**的文本与图片资源编辑行为：段落以提交后渲染配合 **Web 临时文本编辑层**
的方式编辑，支持组合输入（IME）、多行、emoji 与单会话撤销；图片资源使用稳定 ID 并兼容读取旧 `src` 值；
资源导入由 **Web app shell** 提供。**原生 UI 继续保留开发，但不做自动验收**；core/资源解析层保持纯边界。

## Scope Note

- 本 capability 的**正式验收面为 Web**（Web 临时编辑层、Web 组合/多行/emoji、Web shell importer）。
- 原生（iOS/Android）文本编辑与资源导入**不再要求运行验收**；原生 UI 保留并继续开发，
  但其证据仅为 `[evidence:compat-static][target:ios|android][executor:linux]`。
- core 与资源解析层的纯边界要求**不因 Web-only 范围而放宽**。

## ADDED Requirements

### Requirement: 段落提交渲染与 Web 临时编辑层

在 **Web** 上，文本编辑 MUST 采用临时文本编辑层获取输入、提交后再由绘制面渲染段落的方式，MUST NOT 让临时编辑层成为持久渲染的组成部分。原生 UI 保留开发，但不构成自动验收面。

#### Scenario: 编辑中临时层

- **WHEN** 用户在 Web 上进入某个段落的编辑
- **THEN** 出现临时文本编辑层承载输入，绘制面在提交前不把该临时内容当作已提交段落

#### Scenario: 提交后渲染

- **WHEN** 用户提交段落编辑
- **THEN** 临时编辑层移除，提交后的段落由绘制面正式渲染

### Requirement: 中文输入法与多行

临时编辑层 MUST 正确处理中文输入法组合输入，并 MUST 支持多行文本的输入与提交，组合过程中的中间态 MUST NOT 被错误提交为最终文本。

#### Scenario: 中文组合输入

- **WHEN** 用户使用中文输入法进行组合输入
- **THEN** 组合中间态仅在编辑层内显示，最终候选文本在确认后才进入提交内容

#### Scenario: 多行输入

- **WHEN** 用户在编辑层内输入包含换行的多行文本并提交
- **THEN** 提交流程保留多行结构并按段落渲染

### Requirement: emoji 支持

文本编辑 MUST 正确支持 emoji，MUST 保持 emoji 的完整码点序列，MUST NOT 在存储或渲染时拆分或破坏 emoji 字符。

#### Scenario: 输入 emoji

- **WHEN** 用户在文本中插入 emoji 并提交
- **THEN** emoji 被完整保留并正确渲染

#### Scenario: 混合文本

- **WHEN** 文本同时包含中文、拉丁字符与 emoji
- **THEN** 各类字符均被完整保留，光标与选择不发生错位

### Requirement: 单会话撤销

一次文本编辑会话 MUST 作为单个撤销单元，撤销 MUST 能一次性还原该会话前的文本状态，MUST NOT 让单次会话被拆成多个撤销步骤。

#### Scenario: 撤销整个会话

- **WHEN** 用户在单次编辑会话中做了多次增删后执行撤销
- **THEN** 文本一次性还原到该会话开始前的状态

#### Scenario: 会话边界

- **WHEN** 用户提交或取消一次编辑会话后再开始新的编辑
- **THEN** 两次会话的撤销单元相互独立，互不混合

### Requirement: 稳定图片资源 ID 与旧 src 兼容

图片资源 MUST 使用稳定且唯一标识，MUST 在引用中保留该标识；读取时必须兼容既有旧 src 值，使旧数据仍能解析到对应资源。

#### Scenario: 稳定标识

- **WHEN** 同一图片资源被多次引用
- **THEN** 每次引用都使用同一稳定标识，而不因编辑或重载而改变

#### Scenario: 旧 src 兼容读取

- **WHEN** 加载包含旧 src 值的既有文档
- **THEN** 旧 src 被解析为对应资源并使图片正常渲染

### Requirement: 导入由 Web app shell 提供

在 **Web** 上，资源导入能力 MUST 由应用外壳（app shell）提供并注入，核心绘制与资源解析层 MUST NOT 自行获取平台文件或媒体权限。

#### Scenario: 通过 Web 外壳导入

- **WHEN** 用户在 Web 上触发图片导入
- **THEN** 由 Web app shell 负责选择与取得资源，并将结果提供给绘制资源层

#### Scenario: 核心层不承担平台获取

- **WHEN** 检查核心绘制与资源解析层的职责
- **THEN** 其中不包含平台文件选择或媒体权限获取逻辑

### Requirement: 文本编辑会话状态不进入持久文档

文本编辑会话中的草稿、输入法组合状态与测量高度等编辑期状态 MUST 只存在于会话对象内，MUST NOT 写入持久文档、MUST NOT 触发 history 或持久化回调，MUST NOT 进入空间索引；只有提交流程才产生文档增量。

#### Scenario: 编辑期状态不写文档

- **WHEN** 用户在一段文本编辑会话中修改草稿、进行输入法组合或更新测量高度
- **THEN** 文档、撤销历史与持久化回调均不发生变化

#### Scenario: 仅提交流程产生文档变更

- **WHEN** 编辑会话提交成功
- **THEN** 只有该次提交产生一次文档增量，编辑期状态本身从未写入文档

### Requirement: 既有文本目标身份与单次提交

编辑既有文本时 MUST 以文档索引、期望笔迹 ID 与期望工具三者共同定位目标；任一不匹配 MUST 视为过期目标并保持文档不变。同一编辑会话 MUST 至多产生一次文档写入；未请求提交、组合进行中或会话已终结时提交 MUST 不写入文档；取消会话 MUST 不触碰文档；空草稿的新建会话提交 MUST 零变更。

#### Scenario: 三元组匹配才生效

- **WHEN** 提交编辑既有文本且索引、期望 ID 与工具均与当前文档一致
- **THEN** 该位置的文本被更新或删除

#### Scenario: 目标过期

- **WHEN** 提交编辑既有文本但文档在该索引处已变化
- **THEN** 不写入文档并返回过期诊断

#### Scenario: 同一会话只写一次

- **WHEN** 对同一已提交会话重复提交
- **THEN** 文档不再发生额外变化

#### Scenario: 取消与空草稿零变更

- **WHEN** 用户取消一次编辑会话，或新建会话的草稿为空并提交
- **THEN** 文档与历史保持不变

### Requirement: 图片资源表纯边界与就绪资源注入

图片资源 MUST 以稳定唯一标识表示并在引用中保留该标识，读取 MUST 兼容既有旧 `src` 值并保留 `src` 作为回退；资源表 MUST 为纯数据结构，MUST NOT 执行 I/O、平台调用、ID 生成或依赖 Skia。文件选择、平台权限与字节解码 MUST 由 app shell 承担，渲染器 MUST 只同步消费已就绪资源。

#### Scenario: 标识命中优先与 src 回退

- **WHEN** 解析携带标识与 src 的引用
- **THEN** 标识已登记时返回对应标识的资源，否则按登记顺序以 src 精确匹配返回首个资源

#### Scenario: 标识冲突不覆盖

- **WHEN** 登记与既有记录相同标识但数据不同的资源
- **THEN** 保留既有记录并返回冲突诊断，不隐式覆盖、不生成新标识

#### Scenario: 资源表无副作用

- **WHEN** 检查资源表的实现职责
- **THEN** 其中不包含文件读取、平台权限、标识生成或 Skia 依赖

#### Scenario: 外壳解码后注入就绪资源

- **WHEN** 用户通过外壳导入图片并交给渲染器
- **THEN** 外壳负责选择、取得权限并解码，渲染器只同步消费已就绪资源，不执行加载、权限、缓存或重试
