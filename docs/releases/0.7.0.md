# 0.7.0 发布候选

本次基于 `main` 的 `2407b93`，同步升级两个公开包：

- `@hamster-note/painting@0.7.0`
- `@hamster-note/painting-board@0.7.0`，精确依赖 painting `0.7.0`

`0.6.0` 已在 npm 发布，不能覆盖。schema 3 controller API 与旧 API 不兼容，因此在 0.x 阶段升级次版本。迁移说明见根 README 和 CHANGELOG。私有的 `painting-pencilkit` 不发布。

## 验证

使用 Node `24.15.0`、pnpm `10.28.2`：

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
node --test scripts/perf/*.test.mjs
pnpm test:ui --workers=2
pnpm test:webkit --workers=2
pnpm build
pnpm pack:dry
pnpm verify:layered
```

发布前确认两个 tarball 包含全部 `exports`、`main`、`module`、`types`、`react-native` 指向的文件，且无已退役的 Skia 产物。真机验证边界仍以 README 为准。

## 发布身份与审批

准备此候选时，本地 `npm whoami --registry=https://registry.npmjs.org` 返回 `ENEEDAUTH`，npm 12 的暂存查询返回 `E401`。上一次 GitHub 发布运行 `40151077137` 在发布阶段返回 `E_STAGE_REQUIRED`，要求先暂存再审批。现有 tag 工作流使用直接 `npm publish`，不能据此认为它能完成本次发布。

需要包维护者在受控环境中配置可用的 npm 身份。若仍采用暂存策略，使用支持 `npm stage` 的 npm 12，在构建并审核候选后分别执行：

```sh
npm exec --yes --package=npm@12.2.1 -- npm stage publish ./packages/painting --registry=https://registry.npmjs.org --tag latest --access public
npm exec --yes --package=npm@12.2.1 -- npm stage publish ./packages/painting-board --registry=https://registry.npmjs.org --tag latest --access public
```

这两条命令只提交暂存版本，不代表已公开发布。由有权限的维护者检查返回的 stage ID，并按 painting、painting-board 顺序审批：

```sh
npm exec --yes --package=npm@12.2.1 -- npm stage approve <stage-id> --registry=https://registry.npmjs.org
```

审批后核验实际版本与 `latest`，再将确切版本交给消费方：

```sh
npm view @hamster-note/painting@0.7.0 version dist.integrity --registry=https://registry.npmjs.org --json
npm view @hamster-note/painting-board@0.7.0 version dependencies dist.integrity --registry=https://registry.npmjs.org --json
npm view @hamster-note/painting dist-tags --registry=https://registry.npmjs.org --json
npm view @hamster-note/painting-board dist-tags --registry=https://registry.npmjs.org --json
```

两个包都可从 registry 安装后，才记录发布成功。本候选尚未发布，也未推送会触发旧发布流程的 `v0.7.0` tag。
